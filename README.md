## 1. 기능

### 디자인 · 품질

- 디자인 시스템: 인라인 SVG 아이콘 셋(`src/lib/icons.ts` — UI 크롬 이모지 전면 제거),
  라이트/다크(시스템 자동, `prefers-color-scheme`), 로즈틴트 그림자·라운드·모션 토큰,
  세그먼트 컨트롤·로딩 스켈레톤·공용 확인 모달(`ConfirmHost`), 눌리는 촉감(`.tap`). 입력·캘린더·
  일기·설정은 시스템 글꼴을 사용하고 브라우저 확대를 제한하지 않는다.
- 정보구조: 하단 5탭 **홈(오늘) / 기록(로그·일기·사진·추억) / 계획(일정·버킷) / 함께(쿡·연결) / 게임**. §10.7
- 품질 게이트: 순수 로직·소스 계약 테스트(`node --test`) + CI 게이트(`deploy-pages.yml`
  의 `test` job — 타입체크+테스트 통과해야 build/deploy). `keepalive.yml`로 Supabase 무료
  1주 미사용 pause 방지.
- 전체 데이터 모델·RLS의 신규 프로젝트 정본은 `supabase/schema.sql`, 기존 프로젝트의 변경 이력은
  `supabase/migrations/`이다. bootstrap과 무중단 변경 경로를 섞지 않는다.

## 4. 인증 (로그인 필수)

- **이메일+비번**. 첫 진입 시 `AuthGate`(로그인/회원가입). 로그인 전 기능 사용 불가.

- 같은 이메일 로그인 = 같은 `auth.uid()` → 커플·데이터가 모든 기기에서 이어짐. (`src/lib/auth.ts`)
- 비밀번호 재설정은 GitHub Pages basePath를 보존하는 `/our-days/reset-password/`에서 PKCE와
  implicit 복구 링크를 처리한다. 새 비밀번호는 8자 이상 영문·숫자 조합을 요구한다.

| `couple_members` | 구성원(최대 2), 애칭·timezone·city. RPC로 가입, 본인 프로필만 update |
| `pokes` | 쿡찌르기(realtime) |
| `couple_events` | 공유 일정(realtime). 반복·메모·알림 오프셋·편집 |
| `couple_photos` | 공유 사진 메타(realtime). 파일은 Storage `couple-photos`(비공개, 커플 폴더 RLS) |
| `deco_entries` | 일기장 페이지(realtime). 사진은 Storage 재사용 |
| `mood_checkins` | 무드(본인 1개 upsert, realtime) |
| `qa_answers` | 오늘의 질문 답변. **내가 답해야 상대 답 SELECT 허용**(`qa_i_answered` SECURITY DEFINER) |
| `push_subscriptions` | 웹푸시 구독(본인 기기) |
| `debug_logs` | 진단/에러 로그(본인) |
| `game_challenges` / `game_attempts` | 게임 아케이드 챌린지/점수. reveal-gate(내가 도전해야 상대 점수 열림, `game_i_played`) + 승패 확정은 `resolve_challenge` RPC 만. 점수 플로시빌리티 트리거 |
| `game_daily` / `game_ranks` | 하루 1판 카운트(KST) / 전체 공개 순위판. 갱신은 `record_play` RPC(일일 캡·최고기록·rank·**표시명=커플 닉네임**). 순위판 SELECT 는 전체 로그인 사용자 공개 |
| `game_profile` | 부루마블 말 스킨(token/owned)·포인트 지출(points_spent). 커플 신뢰 모델(클라 계산) |
| `board_games` | 부루마블 진행 상태(`state` jsonb + version 낙관적 락). 룰은 클라, 서버는 차례 소유·버전만 강제 |
| `couple_island` | 우리 섬(메인 게임) 상태(커플당 1행 · `state` jsonb + version 낙관적 락). 차례 없이 둘 다 자유, `island_action` 이 버전만 강제 |
| `activity_events` / `activity_reads` | 서버 트리거 기반 활동함과 사용자별 마지막 읽은 시각 |

신규 빈 프로젝트는 [`supabase/schema.sql`](supabase/schema.sql)을 한 번만 실행한다. 기존 프로젝트는
[`supabase/migrations/`](supabase/migrations/)의 아직 적용하지 않은 SQL만 시간순으로 실행한다.
`schema.sql`은 기존 핵심 테이블을 감지하면 데이터 삭제 전에 중단된다. 질문 풀은 번들 JSON
(`src/lib/questions.ts`, 날짜 시드).

**⚠ 오늘의 질문 = 회차 id (2026-09-26 컷오버)** [사용자: "겹치는 질문 나왔을경우 이전 답변이 적혀져있어
새로운 질문이 필요해"] 질문이 75개라 75일마다 같은 질문이 돌아왔고, 답이 질문 번호(`q12`)에만 묶여서
예전 답이 '이미 쓴 답'으로 떴다(상대의 예전 답까지 바로 열렸다). 지금은 365개이고 컷오버 뒤엔 **새 질문
290개가 먼저** 돈다. `question_id` 에 날짜를 붙여(`q12@2026-09-26`) 같은 질문이 와도 새 회차로 답한다 —
DB 변경 없음(텍스트 칸, unique 가 회차마다 따로 걸린다). 지난 회차 답은 "지난번엔"으로 접어 둔다.
- 질문을 늘릴 땐 배열 **끝에만** 붙이고 `ROTATION` 에 (배포 **다음 날 이후**의 fromDay, 새 길이) 한 줄.
  배포 당일로 잡으면 한쪽이 옛 번들인 동안 둘이 다른 질문에 답해 영영 안 묶인다.
- 질문 번호·날짜는 `questionIndex`/`questionDate` 로만 읽는다(옛 id `q12` 와 새 id 가 섞여 있다).

## 6. Edge Functions · 크론

- `send-poke-push`: 쿡찌르기 → 상대 구독으로 web-push. `{test:true}`면 내 구독으로 강제(force) 자가 테스트.
- `daily-reminders`: 주년/커스텀 기념일 D-7/3/1/당일 계산 → 양쪽 푸시. `x-cron-secret` 보호.
- `manage-account`: 사용자 JWT 재검증 후 Storage → DB → Auth 순서로 계정과 개인 데이터를 삭제.
- `media-gc`: 기본 dry-run. 24시간 이상 고아 파일을 참조 2회 확인·명시 승인·회당 200개 상한으로 정리.
- **pg_cron** `'0 0 * * *'`(09시 KST) → pg_net 으로 daily-reminders 호출.
- VAPID 비공개키/`CRON_SECRET`은 함수 시크릿(`supabase secrets`).

## 7. 배포 · 운영

**프론트(자동)**: `main` push → Actions(`.github/workflows/deploy-pages.yml`) 정적 빌드·배포.
```bash
git push origin main         # → 약 1분 후 라이브
gh run watch                 # 진행 확인
```
캐시로 옛 화면이 보이면 앱 완전히 닫았다 다시 열기(SW가 no-store로 최신 문서 로드).

> 운영 프론트 배포 대상은 위 GitHub Pages URL 하나뿐이다. 다른 호스팅 사이트나 도메인에는 배포하지 않는다.

**백엔드(수동)** — Supabase 직접:
- 신규 빈 프로젝트: 대시보드 SQL Editor에서 `supabase/schema.sql`을 **최초 1회만** 실행.
- 기존 프로젝트: `supabase/migrations/*.sql` 중 미적용 파일만 시간순으로 실행. `schema.sql` 재실행 금지.
- 실행 전 백업과 대상 project ref를 확인하고, 실행 후 정책·컬럼·Realtime 등록을 읽기 검증한다.
- 함수: `SUPABASE_ACCESS_TOKEN=<토큰> supabase functions deploy <name> --project-ref tqegatiuembcvphxmujl --use-api` (daily-reminders 는 `--no-verify-jwt`).
- 시크릿: `supabase secrets set KEY=… --project-ref …`. 인증설정: Management API `PATCH /v1/projects/{ref}/config/auth`.

보다 좁아지지 못해 마지막 칸부터 밀려난다.

**⚠ 루트(html/body)의 가로 클립은 iOS 에서 `position: fixed` 를 죽인다 (2026-08-31).**
[사용자 리포트 "사파리에서 하단 네비게이션바가 스크롤하면 위로 올라간다"]
녹화를 프레임 단위로 재 보니 GNB 와 네온 베젤이 **문서 스크롤량과 1:1 로** 같이 올라갔고
(t=0.8: 콘텐츠 −75px / 베젤 −75px), 최대 554px 올라간 채 **멈춰** 있다가 스크롤을 0 으로
되돌리자 제자리로 왔다. **베젤 높이는 1354px 로 내내 고정** — 통째로 밀린 것이지 눌린 게
아니다. 즉 fixed 의 컨테이닝 블록이 뷰포트가 아니라 **문서**였다(= 사실상 absolute).
- 원인: **루트의 overflow 는 뷰포트로 전파된다.** WebKit 은 뷰포트가 클립된 상태에서
  fixed 레이어를 뷰포트 고정으로 잡지 못한다. `overflow-x: hidden` 으로 더 유명한 고질 버그고
  `clip` 도 같은 경로를 탄다. → `@supports (-webkit-touch-callout: none)` 로 iOS 에서만 되돌린다.
- ⚠ **html 만 되돌리면 소용없다.** 루트가 visible 이면 이번엔 body 값이 뷰포트로 전파된다.
- 모달·시트가 멀쩡했던 이유: `scrollLock` 이 오버레이 동안 body 를 fixed 로 묶어 스크롤을
  0 으로 만든다. 스크롤이 0 이면 이 버그는 드러나지 않는다 — **GNB 만 상시 노출이라 걸렸다.**
- 같은 녹화에 **두 번째 원인**도 찍혔다: 한 프레임에서 베젤 위변은 제자리인데 아래변만
  264px(≈144 CSS px) 올라갔다(= 높이가 줄었다 = 패딩). `--vv-bottom` 이다 — 삼성 인터넷
  하단 주소창용 보정이라 WebKit 엔 근거가 없다. ViewportFit 이 iOS 에서 이 보정을 끈다.
- 크로미움은 무사하다(실측: 루트 clip 이 있어도 fixed 의 offsetParent 가 null 로 유지) →
  삼성 인터넷용 그물은 그대로 둔다. `iosfixed.test.ts` 가 넷을 잠근다.

**펫 탭 점프 — 캔버스는 자기 안에서 움직인다 (2026-08-05).** 섬 무대는 하늘·잔디·나무·펫이
**한 장의 캔버스**라, 래퍼에 CSS transform 을 걸면 그림 전체가 통째로 흔들린다
(사용자: "네모 픽셀 자체가 움직이고"). `PetTapFx stageMotion={false}` 로 무대 변형을 끄고,
`PixelPet` 이 `tapHop(combo, elapsed)`(순수·정수 논리픽셀) 으로 **스프라이트 좌표만** 옮긴다.
점프 높이는 단계가 아니라 **연타 수에 비례**한다(홈은 `--pet-hop` CSS 변수로 같은 개념).
⚠ 콤보는 state 가 아니라 **ref** 로 센다 — state 면 같은 틱의 연타가 stale 값을 읽어 1 에서 멈춘다.

메시지에 `pb-` + 대괄호 + `calc(...)` 모양의 **예시 문자열**을 넣었더니 그게 후보로 잡혀
유효하지 않은 규칙이 생성됐고, globals.css 파싱이 통째로 실패했다(= 앱 스타일 전멸).
`next build` 는 조용히 통과했고 **브라우저 콘솔에서만** 잡혔다.

같은 실수를 이 문서를 쓰다가 한 번 더 했다 — 위 사례를 **문자 그대로** 적어 놓는 순간
README 가 스캔되어 버그가 되살아났다. 그래서 이 문단엔 문제의 문자열을 조각내서 적는다.
규칙: **설명·메시지·주석에 클래스 문법을 통짜로 쓰지 마라.** 꼭 보여야 하면 조각내거나
`{ }` 로 끊어라(`pb-{[}calc(...){]}`).

**⚠ 소스 스캔 테스트는 주석을 먼저 지워라.** 이 저장소는 '왜 그렇게 했는지'를 주석에 길게
남기는 스타일이라, 전체 소스를 정규식으로 훑으면 설명문이 먼저 잡힌다(한 세션에 3번 오검출).
`src.replace(/\/\*[\s\S]*?\*\//g,"").replace(/\/\/[^\n]*/g,"")` 를 거치거나
`className="..."` 문자열만 추출해서 봐라.

## 10.7 정보구조 — 탭 하나 = 질문 하나 (2026-09-24 개편)

[사용자: "지금 메뉴가 너무 파편화 되어있는 것 같아 홈/기록/계획/함께 여기에서 모을 수 있는걸 다시 모으고
개편해보자"] 같은 기능이 두세 곳에 흩어져 있었다(작년 오늘 두 벌, 기분 입력은 함께·요약은 일기장, 기념일
편집은 홈·캘린더, 대표사진은 세 곳). 원칙은 둘 — **탭 하나 = 질문 하나**, **같은 종류는 고치는 곳이 하나**
(다른 곳엔 미리보기와 바로가기만). `todayhub.test.ts` 가 잠근다.

| 탭 | 질문 | 담는 것 |
|---|---|---|
| 홈 | 오늘 | 히어로 · 🔔 활동함 · **오늘의 우리**(3초 로그 → 기분 한 줄 → 오늘의 질문, 머리에 "오늘 3개 중 N개"와 모닥불) · 다음 일정 한 줄 · 작년 오늘(있는 날만) · 빠른 실행 |
| 기록 | 지난 우리 | 로그 · 일기 · 사진 · **추억**(작년 오늘 · 월간 리캡 · 이 달의 기분) |
| 계획 | 앞으로 | 일정(맨 위 **다가오는 기념일** — 편집·삭제는 여기서만) · 버킷 |
| 함께 | 서로 말 걸기 | 쿡 채팅 · 연결 상태·초대 · 연결 관리 |

- **활동함·알림은 경로 표 하나**(`lib/activity` 의 `activityRoute`). 예전엔 기분·질문 행을 누르면 **홈**으로
  갔는데 두 카드는 **함께**에 있었다(죽은 링크). 홈으로 가는 경로는 카드 id(`today-mood` 등)까지 가리키고,
  `focusHomeCard` 가 스크롤 + 테두리 반짝임으로 어느 카드인지 보여 준다. 새 활동 종류를 추가하면 switch 의
  `never` 가 타입 오류를 낸다 — 경로 없는 행을 만들 수 없다.
- **푸시 알림도 같은 표**: 보낼 때 `url: ./?go=<종류>`(Edge 가 url 을 그대로 전달 — 함수 재배포 불필요),
  새 창은 부팅 때 `?go=` 를 읽고 지우고, 열린 앱은 SW 가 `postMessage({type:"openRoute"})`. 서버 예약 푸시
  (기념일·오늘 남기기)는 함수가 url 을 `./` 로 박아 둬서 홈으로 연다 — 홈에 다음 일정·오늘의 우리가 있다.
- **진행 표시는 카드가 알려 준다**(`onStatus`). 머리에서 따로 조회하면 '카드엔 했다는데 머리엔 안 했다'가 생긴다.
  로그는 **지금 슬롯**(오전/오후) 기준 — 카드의 '3초 남기기' 버튼과 같은 기준이다.
- **🔔 시트는 연 순간의 읽음 시각(since)으로 새 소식을 칠한다.** 열자마자 읽음 처리가 되므로 지금의 lastRead 로
  칠하면 새 소식 표시가 곧바로 사라진다. 조회·구독은 앱이 한 번 들고(`useActivityInbox`) 종에 개수를 단다.
- **홈의 작년 오늘은 가벼운 조회**(`listOnThisDaySnapshot`) — 전체 스냅샷은 네 테이블을 통째로 받는다. 날짜 칸은
  `in()`, 시각 칸은 KST 하루 범위들의 `or`(값은 큰따옴표로 감싼다 — 시각의 ':'). 2/29 는 윤년에만(`pastSameDays`).
- 대표사진 액자(CoverFrame)와 '우리 현황' 카드(CoupleActivity)는 지웠다. 액자는 홈 히어로·사진첩과 같은 사진의
  세 번째 자리였고, 우리 현황의 주간 개수는 추억의 월간 리캡이 같은 말을 한다(스트릭만 '오늘의 우리' 머리로).

### 14.2 사냥 (방치형)

`lib/hunt.ts`(순수 엔진) + `components/HuntGame.tsx`(화면) + `island/HuntStage.tsx`(캔버스).
상태는 `couple_island.state` 안 `s.hunt` — **DB 마이그레이션이 없다**(hero 와 같은 방식).

- **중심은 전투 연출이 아니라 `settle(state, now, atk, lv, offline)`** 이다. 화면이 켜져 있든
  (1초마다) 껐다 켰든(몇 시간을 한 번에) **같은 함수**를 부른다. 계산을 화면에 흩뿌리면
  '보고 있을 때만 이득'이 생겨 방치형이 아니게 된다. hunt.test.ts 가 쪼갠 정산과 한 번에 한
  정산이 **정확히 같은 결과**를 내는지 잠근다.
- **무기가 주역**: DPS = max(1, 무기 atk) × (1 + (Lv−1)×0.12). 맨손 Lv30 < 전설무기 Lv1
  이라는 서열을 테스트가 강제한다. 무기는 곱이 아니라 **계단**(2 → 8 → 30)이라 산 순간이 체감된다.
- 오프라인은 **10시간 캡 · 효율 50%**. 캡이 없으면 한 달 방치 후 접속 한 번으로 게임이 끝난다.

**경제 재조정 (2026-08-07)** — [사용자 리포트 "자동사냥하면 하트가 몇천개씩 벌리는데"]

실측이 그대로였다. **맨손 Lv1 로도 12시간에 3,713 하트**, 수박검이면 27,375 —
장비 9종 총액이 51,150 인데 **하루 반이면 다 샀다.** 원인이 셋이었다.

1. **마리당 보상이 스테이지를 따라 선형으로 끝없이 커졌다**(`4 + stage*1.6`).
   스테이지에 상한이 없으니 수입에도 상한이 없다. → 로그 성장 + 천장(`KILL_REWARD_CAP`).
2. **온라인 정산에는 상한이 아예 없었다.** 오프라인만 12시간 캡이 있어서,
   사냥 화면을 켜 두면 무제한이었다 — '방치형'이 아니라 **켜 두기 경쟁**이다.
   → **일일 획득 한도**(KST 자정 리셋)를 온·오프라인 **양쪽에** 건다. 이게 진짜 상한이다.
3. **HP 가 1.18^s 지수인데 공격력은 계단**이라, 60스테이지에서 한 마리에 4.6시간이 걸렸다.
   보상을 조이자 후반 수입이 아예 무너졌다 → HP 성장 1.18 → **1.105**.

⚠ **한도를 고정값으로 두면 비싼 무기를 살 이유가 사라진다.** 1차 조정에서 실제로
  나무막대와 수박검의 하루 수입이 **둘 다 1,800** 으로 같아졌다. 지금은 한도가
  **도달 스테이지에 비례**한다(`dailyCap(best)` = 300 + best×38, 천장 4,000).

⚠ **한도는 정산 중에 오른 스테이지까지 반영한다.** 시작 시점 best 로 고정하면
  신규 첫 12시간이 338 밖에 안 나온다("처음 켰는데 왜 이것밖에"). 스테이지가 오를 때마다
  다시 계산한다.

⚠ **한도에 닿아도 처치·스테이지는 계속 오른다.** 진행까지 멈추면 그건 상한이 아니라 벌이다.
  그리고 오늘 오른 스테이지가 **내일의 한도**를 올린다.

**자동 플레이 테스트가 잡은 실제 버그 셋** — 물리가 순수 함수라 봇을 돌려

1. 거품 수명(7.8초)이 가둠 시간(6초)보다 먼저 끝나면 **몬스터가 주인 없는 거품에 갇힌 채**
   영영 남아 스테이지가 안 깨졌다. → 사라지는 거품은 반드시 풀어 준다.
2. 가둔 거품이 천장까지 떠올라 아래층에서는 손도 못 댔다(가두고 터뜨린 게 0마리).

3. 바닥에서 첫 발판까지 48px 인데 점프 최고 높이가 45px 이라 **아래층에 갇혔다**.

**아트 — 왜 다시 그렸나 (2026-08-07)**

1차판은 섬의 펫(48×48)과 사냥 몬스터(32×32)를 줄여서 썼다. 사용자 판단은
"더 캐릭터있게, 너무 선명하지않아, **너 보글보글 모르니?**" 였고 둘 다 맞았다.

원인이 둘이었다.

- **줄이면 표정이 사라진다.** 48을 16으로 줄이면 눈·입이 한두 칸으로 뭉개져
  실루엣만 남는다. → `lib/pixelbubble.ts` 에 **전용 16×16 을 손으로 찍었다**.
- **배경이 문제였다.** 섬과 같은 시간대별 하늘 그라데이션 위에 밝은 캐릭터를 올렸으니
  대비가 죽는다. 원작(Taito 1986)은 **배경이 검정**이고, 그게 이 게임이 선명한 이유다.
  → 무대는 검정 + 채도 높은 발판. 캐릭터에는 **조명을 아예 안 먹인다**.
  액션 게임은 분위기보다 판독성이다.

원작을 보고 맞춘 것: 주인공은 **등에 돌기가 난 둥근 공룡**(큰 눈·크림색 배·작은 발),
적은 Zen-Chan(태엽 인형)·Monsta(보라 고래)·Banebou(용수철)·Pulpul(프로펠러)·Hidegons(털),
그리고 **거품에서 풀려난 적은 분홍으로 변하고 빨라진다**(1차판은 머리 위 빨간 점이었다 — 원작이 아니다).

`pixelbubble.test.ts` 가 잠그는 것들:

- 얼굴이 있는가 — 눈동자·흰자·입·등돌기가 **각각 셀 수 있을 만큼** 있는가
  (입이 없어서 '통통한 새'로 읽혔던 게 실제 1차판이다)
- 몬스터 5종의 **실루엣**이 서로 다른가(색만 다른 같은 몸이면 결국 같은 몬스터다)
- 모든 색이 **검정 배경 위에서 보이는가**(휘도 하한). 등 돌기를 어두운 톤으로 뒀다가
  통째로 안 보인 적이 있다 — 검정 배경에서 어두운 색은 사라진다.
- 종마다 색이 다른가(우리 히어로라는 게 남아야 한다)

⚠ 도트를 눈으로 확인할 방법이 필요하다. 프리뷰 pane 이 안 뜨면 스크린샷을 못 찍으니,

### 14.4 개발/검증 유의

- **배포 flake**: `deploy-pages.yml` deploy 단계가 간헐 "Deployment failed, try again later"(GitHub
  Pages 이슈, 코드 무관). 해법: `gh workflow run deploy-pages.yml --ref main` 새 dispatch. SHA 고착
  (deployment_failed/cancelled)이면 **빈 커밋으로 새 SHA** 만들어 재배포.
- **프리뷰 검증 제약**: 헤드리스 프리뷰 탭은 rAF/setTimeout throttle(마이크로태스크는 진행) → 타이밍성
  게임 자동 구동·부루마블 인게임(상대 연결 필요)은 **동일 CSS 목업 DOM 주입**으로 시각 검증(주사위/축하
  팝업/보드 동일 기법). 자동 초고속 점수는 anti-cheat 로 거부됨.
- **회귀 lock 룰**: 버그 fix 마다 `src/**/*.test.ts`에 소스-스캔/로직 테스트 동반(방향 계약·submitMatch
  순서·닉네임 클로버링 금지·상점 가격·mood note truncate 금지 등).
