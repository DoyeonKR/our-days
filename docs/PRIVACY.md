# 개인정보·데이터 관리 안내 — 하루

시행일·마지막 변경: 2026-08-25

이 문서는 실제 제품의 저장·내보내기·삭제 동작을 운영 관점에서 설명한다. 라이브 앱에서도
`/our-days/privacy/` 경로로 같은 내용을 확인할 수 있다.

## 1. 처리 항목

- 계정: 이메일 주소, Supabase Auth 인증 정보. 앱 데이터베이스는 비밀번호 원문을 보관하지 않는다.
- 프로필·연결: 커플 ID, 애칭, 시작일, 초대코드와 만료일, 선택 도시·시간대.
- 서비스 기록: 일정, 버킷리스트, 사진, 일기, 오늘 로그, 기분, 질문 답변, 쿡, 활동함, 게임 상태.
- 알림·진단: Web Push 구독, 알림 종류와 조용시간, 앱 진단 로그.
- 기기 로컬: 작성 중 초안, 화면 테마, 캐시. 이 항목은 현재 브라우저에만 저장된다.

## 2. 이용 목적

두 사람의 기록 동기화, 일정·활동 알림, 추억 리캡, 오류 진단에 사용한다. 선택 도시의 날씨를
가져올 때 Open-Meteo에는 도시 좌표만 보내며 계정 ID·이메일·작성 내용은 포함하지 않는다.

## 3. 처리 인프라

- Supabase: Auth, PostgreSQL, 비공개 Storage, Realtime, Edge Functions.
- GitHub Pages: 정적 웹앱 파일 제공.
- Open-Meteo: 선택 도시의 현재 날씨 조회.
- 브라우저·운영체제 Web Push 전달망: 푸시 전달.

개인정보를 판매하지 않으며, 서비스 기능 제공에 필요한 위 처리자 외에 임의 제공하지 않는다.

## 4. 보관과 정리

- 기록은 사용자가 직접 삭제하거나 계정을 삭제하기 전까지 보관하며, 오래됐다는 이유로 자동 삭제하지 않는다.
- 업로드 도중 연결이 끊겨 DB 어느 곳에서도 참조하지 않는 미디어는 24시간 보호 기간 뒤에도 참조를
  두 번 확인하고 운영자가 `confirm=true`로 승인한 경우에만 회당 200개까지 정리한다. 자동 일정은 없다.
- 푸시 발송 응답이 404/410인 만료 구독은 정리한다.

## 5. 이용자 제어

- 설정 → 데이터에서 RLS로 현재 계정이 조회할 수 있는 기록을 JSON으로 내보낼 수 있다.
- 사진·일기 사진·로그 영상은 ZIP으로 내보낼 수 있다. 브라우저 메모리 안전을 위해 250MB 상한을 둔다.
- ‘이 기기 데이터 초기화’는 캐시·초안·화면 설정만 지우고 계정과 서버 기록은 보존한다.

## 6. 계정 삭제

설정 → 데이터 → 계정 삭제에서 현재 비밀번호로 다시 인증한다. 서버는 미디어 → DB → Auth 순서로
삭제하며 앞 단계가 실패하면 성공으로 표시하지 않는다.

- 상대가 남아 있으면 삭제 사용자의 개인 기록·식별 정보를 지우고, 공유 일정·버킷리스트는 상대가
  계속 사용할 수 있도록 유지한다. 양쪽 사용자 ID가 포함된 경쟁 기록은 제거한다.
- 혼자 남은 공간이면 공유 공간과 그 하위 데이터도 함께 삭제한다.
- 완료된 인증 계정 삭제는 복구할 수 없으므로 먼저 내보내기를 권장한다.

## 7. 보안과 문의

HTTPS, PostgreSQL RLS, 비공개 Storage 정책을 사용한다. 문의는
[GitHub Issues](https://github.com/DoyeonKR/our-days/issues)로 받되, 공개 게시판에는 이메일·초대코드·
사진·비밀번호 등 개인정보를 올리지 않는다.
